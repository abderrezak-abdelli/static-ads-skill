# Caveman Language Protocol ## What It Is A compact, telegraphic writing style for checkpoint.md past-context sections. Saves tokens, saves space, keeps checkpoint scannable. ## Rules 1. **Drop articles**: no "the", "a", "an" 2. **Drop pronouns**: no "I", "we", "they" 3. **Drop auxiliary verbs**: no "was", "had been", "will be" 4. **Use symbols**: `→` for causation, `+` for and, `→` for then, `×` for failed, `✅` for done, `⚠️` for partial, `❌` for broken 5. **Compress names**: `opencode` not "OpenCode application", `nvidia` not "NVIDIA NIM API" 6. **One line per event**: no paragraphs 7. **No explanations**: just facts, context lives in logs/ ## Examples | Full English | Caveman | |---|---| | We installed OpenCode and it worked | installed opencode ✅ | | The NVIDIA API returned a 404 error when we tried chat completions | nvidia chat/completions → 404 ❌ | | We ran brew cleanup and freed 18GB of disk space | brew cleanup → 18GB freed ✅ | | User said not to process the unprocessed files yet | unprocessed files → wait for user go-ahead | | I tried to configure the local provider but it only partially worked | local provider config → partial ⚠️ | ## When To Use - `checkpoint.md` → PAST CONTEXT section only - Quick status updates in logs when space matters ## When NOT To Use - Any file where clarity > compression - /XXX.xx - Client-facing anything
